## 1. 目标

在现有单页管理后台中补齐行业模板管理能力，使用户可以：

- 以卡片形式浏览内置模板和自定义模板；
- 查看实体、关系、指标、别名等模板详情；
- 在确认影响范围后，以安全合并方式应用模板；
- 上传 JSON、YAML 或 YML 文件，先校验和预览，再创建模板；
- 通过结构化表单新建和编辑模板；
- 编辑内置模板，并在需要时恢复预置版本；
- 编辑或删除自定义模板；
- 获得明确的成功、跳过和失败结果。

## 2. 已确认的产品规则

1. 内置模板允许编辑。修改内容作为用户覆盖保存，内置源定义保持不变。
2. 内置模板提供“恢复预置”操作，不允许删除。
3. 自定义模板允许创建、编辑和删除。
4. 上传支持 `.json`、`.yaml` 和 `.yml`，文件读取后先校验和预览，用户确认后才保存。
5. 应用模板采用安全合并：已有实体、关系、指标和别名均不覆盖，只新增缺失项。
6. 应用确认弹窗中的影响数量必须由后端根据当前配置实时计算。
7. 页面布局采用“模板卡片网格 + 右侧详情抽屉”；编辑使用大尺寸结构化弹窗。

## 3. 范围外事项

- 不提供多用户权限、审批流或模板所有权管理。
- 不提供模板版本历史，只保留当前用户覆盖和内置基线。
- 不将模板存储迁移到数据库。
- 不提供远程模板市场、模板下载中心或 Git 同步。
- 不允许应用模板时强制覆盖现有语义配置。

## 4. 后端架构

### 4.1 模块边界

- `app/templates.py`：继续保存三套内置模板，作为不可变基线。
- `app/template_models.py`：定义模板、实体、关系、指标、上传内容和接口结果的 Pydantic 模型。
- `app/template_store.py`：负责模板合并、解析、校验、持久化、恢复和删除。
- `app/template_apply.py`：计算应用影响并执行安全合并，保证预览和实际应用使用同一套判定逻辑。
- `app/main.py`：只负责声明 HTTP 路由、转换异常和调用上述服务。

### 4.2 持久化格式

用户内容写入 `data/industry_templates.json`：

```json
{
  "version": 1,
  "overrides": {
    "manufacturing": {
      "name": "制造业通用",
      "description": "用户修改后的描述",
      "entities": {},
      "relationships": [],
      "metrics": {},
      "aliases": {}
    }
  },
  "custom": {
    "automotive-parts": {
      "name": "汽车零部件",
      "description": "汽车零部件行业语义模板",
      "entities": {},
      "relationships": [],
      "metrics": {},
      "aliases": {}
    }
  }
}
```

`TemplateStore` 在读取时执行以下合并：

- 没有覆盖记录的内置模板直接返回基线；
- 有覆盖记录的内置模板返回完整覆盖版本，并标记 `customized: true`；
- 自定义模板标记 `origin: "custom"`；
- 列表和详情均返回 `origin`、`customized` 以及实体、关系、指标、别名数量。

写入使用进程内锁、同目录临时文件和 `os.replace()` 原子替换。文件不存在时视为空覆盖层；文件格式损坏时返回明确错误，不静默清空已有模板。

### 4.3 模板标识

- 模板 ID 匹配 `^[a-z0-9]+(?:-[a-z0-9]+)*$`。
- 新建后模板 ID 不可修改。
- ID 与内置模板或自定义模板冲突时，新建接口返回 `409`。
- 上传内容必须包含 `id`；上传预览允许用户在保存前修改 ID。

## 5. API 设计

### 5.1 模板浏览

```text
GET /templates
GET /templates/{template_id}
```

列表接口返回摘要和统计数量；详情接口返回完整模板及来源元数据。

### 5.2 校验、创建和编辑

```text
POST /templates/validate
POST /templates
PUT  /templates/{template_id}
```

上传校验请求：

```json
{
  "filename": "automotive-parts.yaml",
  "content": "id: automotive-parts\nname: 汽车零部件\n..."
}
```

校验接口根据扩展名使用 `json.loads()` 或 `yaml.safe_load()`，返回标准化后的完整模板、摘要统计、冲突提示和校验结果，不写文件。

创建和编辑接口接收标准化 JSON。编辑时请求体 ID 必须与路径 ID 一致；内置模板写入 `overrides`，自定义模板写入 `custom`。

### 5.3 删除和恢复

```text
DELETE /templates/{template_id}
POST   /templates/{template_id}/reset
```

- 删除仅适用于自定义模板；删除内置模板返回 `400`。
- 恢复仅适用于内置模板；操作会删除对应覆盖记录。
- 模板不存在返回 `404`。

### 5.4 应用预览和执行

```text
GET  /templates/{template_id}/apply-preview
POST /templates/{template_id}/apply
```

预览和执行共用一套差异计算函数。结果按类型列出新增项和跳过项：

```json
{
  "template_id": "manufacturing",
  "added": {
    "entities": ["ProductionRecord"],
    "relationships": ["Machine-HAS_PRODUCTION-ProductionRecord"],
    "metrics": ["production_output"],
    "aliases": ["车间"]
  },
  "skipped": {
    "entities": [{"name": "Machine", "reason": "同名实体已存在"}],
    "relationships": [],
    "metrics": [{"name": "energy_consumption", "reason": "同名指标已存在"}],
    "aliases": []
  },
  "counts": {
    "added": {"entities": 1, "relationships": 1, "metrics": 1, "aliases": 1},
    "skipped": {"entities": 1, "relationships": 0, "metrics": 1, "aliases": 0}
  }
}
```

安全合并规则：

- 实体按名称判重；存在即跳过，不判断或覆盖物理映射。
- 关系按 `(from, relation, to)` 判重；存在即跳过，避免改变已有连接条件。
- 指标按名称判重；存在即跳过。
- 别名按别名键判重；存在即跳过，不改变当前映射值。
- 新增关系写入前与当前完整关系列表合并，再调用现有注册中心保存方法，不能用模板关系直接替换现有关系。
- 执行完成后返回与预览相同的详细结构，并增加 `applied: true`。

## 6. 数据校验

模板保存或应用前必须满足：

- 名称是去除首尾空格后的非空字符串；
- 描述是字符串；
- 至少包含一个实体；
- 实体名称非空，实体配置包含描述和属性对象；可选 `physical_mapping` 必须是对象，其中 `columns` 必须是字段映射对象；
- 属性名称非空，属性类型只允许 `string`、`number`、`integer`、`boolean`、`date`、`datetime`；
- 每条关系包含 `from`、`relation`、`to` 和 `on`；
- 关系起点和终点均引用当前模板内的实体；
- 指标名称非空，必须包含非空表达式；单位可为空，同义词必须是字符串数组；
- 别名和值均为非空字符串；
- 上传文件扩展名必须受支持，UTF-8 内容不超过 2 MiB；
- YAML 只使用 `yaml.safe_load()`，顶层必须是对象。

接口将字段级问题作为数组返回，包含稳定的字段路径和中文提示，供编辑器定位到对应区域。

## 7. 前端设计

### 7.1 文件边界

- `app/static/index.html`：增加侧边栏入口、模板面板容器、详情抽屉和通用弹窗挂载点。
- `app/static/template-management.css`：模板卡片、抽屉、编辑器、上传区、确认和结果视图样式。
- `app/static/template-management.js`：模板 API、页面状态、渲染、表单编辑、文件读取、校验、确认和结果交互。

模板功能不继续堆叠到现有大型内联脚本中。新脚本沿用当前原生 JavaScript 和现有视觉风格，不引入前端框架或构建工具。

### 7.2 模板列表

- 侧边栏增加“🏭 行业模板”，页面标题同步更新。
- 顶部提供搜索框、“上传模板”和“新建模板”。
- 卡片展示名称、描述、来源标签、已修改标签及四类统计。
- 卡片提供“查看详情”和“应用”快捷操作。
- 搜索按模板 ID、名称和描述在前端过滤。

### 7.3 详情抽屉

- 从右侧打开，不离开卡片列表。
- 展示基本信息和实体、关系、指标、别名四个分区。
- 操作包括编辑、应用；内置且已修改时显示恢复预置；自定义模板显示删除。

### 7.4 结构化编辑器

- 大尺寸弹窗包含“基本信息、实体、关系、指标、别名”五个标签页。
- 实体页支持增删实体和属性。
- 关系页通过当前模板实体下拉框选择起点和终点。
- 指标页编辑表达式、单位和同义词。
- 别名页维护业务叫法与字段名。
- 创建模式允许输入 ID；编辑模式锁定 ID。
- 保存前调用后端校验，错误显示在对应标签页和字段旁。

### 7.5 上传流程

1. 用户选择或拖放 JSON/YAML 文件。
2. 浏览器拒绝大于 2 MiB 或扩展名不受支持的文件。
3. 浏览器读取文本并调用校验接口。
4. 预览显示名称、ID、来源文件、统计和校验问题。
5. 校验通过后可以直接创建，或进入结构化编辑器调整后创建。

### 7.6 应用流程

1. 用户点击“应用”。
2. 前端请求应用预览并展示新增、跳过数量及可展开原因。
3. 用户确认后调用应用接口，期间禁用重复操作。
4. 成功结果展示实际新增和跳过详情，并提供“查看语义图谱”。
5. 失败时保留弹窗内容并显示后端错误，允许重试或取消。

## 8. 安全与异常处理

- 所有用户提供的模板名称、描述、实体名和错误文本在插入 HTML 前统一转义。
- 前端不把上传内容直接写入 `innerHTML`。
- 解析错误、字段错误和业务冲突返回可读中文信息，不泄露堆栈。
- HTTP 状态码约定：格式或规则错误 `400`、模板不存在 `404`、新建 ID 冲突 `409`。
- 所有异步按钮在请求期间禁用，结束后恢复，防止重复保存或重复应用。
- 模板存储写入失败时保留原文件，接口返回失败，不把内存状态当作已保存状态。
